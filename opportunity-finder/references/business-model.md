# AI Micro-Product Portfolio Business Model

The default model is portfolio commerce, not one-SaaS-at-a-time entrepreneurship.

## Core loop

Detect → Build → List → Collect → Grow / Harvest / Sell / Kill → Repeat

## Product roles

- FREE_ANCHOR: buys installs, ranking, reviews, author trust, first-party demand, or opt-in telemetry.
- PAID_ACTIVATION: low-friction first purchase, often low price.
- PAID_UTILITY: clear practical value and cash flow.
- PAINKILLER: prevents expensive failure/rework and can price higher.
- BUNDLE_COMPONENT: strengthens a coherent product cluster.
- EVENT_SKU: exploits a short-lived release/change window.

## Preferred economics

1. user uses own Claude/Codex/WorkBuddy subscription;
2. local scripts/compute;
3. BYOK for third-party APIs;
4. no server/database unless demand already proves it worthwhile;
5. minimal support by design;
6. multi-market distribution from one maintained core.

## Free rule

Free is a commercial choice only when it acquires a measurable asset. Examples:

- install/ranking position;
- reviews;
- author reputation;
- demand submissions;
- privacy-safe opt-in telemetry;
- conversion into a closely related paid tool.

## Post-launch state

- GROW: rising installs/revenue; improve or expand.
- HARVEST: still sells; stop spending development time.
- ANCHOR: keep free because strategic acquisition value is proven.
- SELL: transferable asset worth selling rather than operating.
- KILL: no money, no distribution value, no useful data signal.

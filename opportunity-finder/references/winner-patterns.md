# Winner Patterns Observed in High-Install Agent Skills

Benchmark snapshot date: 2026-08-26.

These are mechanisms to reuse, not products to clone.

## 1. Discovery sits at a powerful gateway

`find-skills` became a category anchor because it appears exactly when users ask for a capability the base agent may not have. Gateway/meta skills can win because they route future demand.

Opportunity Finder should similarly trigger on: “what should I build?”, “what is newly painful?”, “find something I can ship this weekend”, and “what is growing around this Skill?”

## 2. Hard behavioral rules outperform vague advice

High-install skills such as grilling, TDD, systematic debugging, and verification-before-completion impose non-negotiable process gates. Their value is not extra prose; it is preventing the agent from taking a common bad shortcut.

Opportunity Finder therefore uses a **kill-first gate**: it must actively search for evidence that invalidates a candidate before recommending SHIP.

## 3. Persistent artifacts create repeat value

Handoff and planning skills create durable files/issues that survive a session. Opportunity research should not disappear in chat. Save structured candidate evidence and decisions locally when the host environment permits it.

## 4. Concrete jobs beat broad intelligence

Popular skills have obvious names and 30-second value propositions: find a skill, browse a page, hand off a session, debug systematically, create a frontend, test before completion.

Opportunity Finder outputs must converge to a concrete product job and launch hypothesis, not “market intelligence.”

## 5. Suites compound distribution

Large repositories frequently contain coherent families of related skills. A successful free anchor can lead to a cluster of adjacent tools. Opportunity Finder should identify potential **category anchors** and related SKU clusters, while avoiding unrelated bulk publishing.

## 6. Current Trend surfaces reveal emerging categories faster than all-time ranks

All-time rank proves accumulated distribution. Trending/Hot surfaces are better for event windows. Use both, and distinguish installed base from current acceleration.

## 7. Raw installs can be distorted by distribution mechanics

The ecosystem supports installing whole repositories and Packs containing multiple Skills. Therefore installs can represent co-installation/exposure rather than deliberate selection of one capability. Cross-check installs with current velocity, source type, duplicate status, first-seen date, GitHub/community evidence, and user outcomes.

## 8. “Anti-slop” / quality-control demand is real but easy to commoditize

Fast-growing anti-slop/design-quality skills show users want AI output that is less generic. But broad style wrappers are easy to copy. Prefer narrow, verifiable quality gates in a specific workflow.
